## Objetivo

Usar esta skill para revisar `spec.md` y detectar ambigüedad, alcance mezclado o requisitos no verificables.

## Flujo

1. Leer `docs/ears.md` y la spec indicada.
2. Clasificar requisitos como ubiquitous, event-driven, state-driven, unwanted behavior u optional feature.
3. Señalar requisitos vagos o no verificables.
4. Proponer redacciones EARS en español.
5. Separar criterios de aceptación de requisitos funcionales cuando estén mezclados.

## Reglas

- No cambiar código.
- No ampliar alcance sin marcarlo como propuesta.
- Si falta contexto, listar preguntas concretas.
